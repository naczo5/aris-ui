Agent Tooling

aris-ui is built to be changed by AI coding agents safely. Everything in this page exists so an agent can compile, verify, and see the result of its edits without a human in the loop.

Read AGENTS.md in the repository root first — it is the agent contract (repo map, commands, conventions, gotchas).

One-command verification loop


make verify

Runs make test + make preview. After any change to rendering, widgets, layout or fonts, this is the loop to run. It never needs a display.

Visual previews (headless)

aris_scene_preview renders named UI scenes into an offscreen GLFW context and writes PNGs — real framebuffer dumps, not mockups:


./build/aris_scene_preview --list                 # scene name<TAB>description
./build/aris_scene_preview --all --out previews   # render everything
./build/aris_scene_preview --scene panel,sliders --out previews
./build/aris_scene_preview --scene text --width 800 --height 600
SceneShows
panelThe full canonical demo panel (all widgets)
buttonsButtons, idle
buttons-hoverFirst button hovered (eased state, simulated mouse)
buttons-pressFirst button held down (simulated press)
togglesToggle on + off
slidersSliders at 0 / mid / full
textMSDF text ramp 11–26 px + colored variants
cardSDF cards at radius 0 / 10 / 20

Behavior notes for agents writing scenes:

  • - --warmup N frames render before the snapshot so hover/press easing settles

    • (default 10 ≈ 166 ms of simulated time).

  • - Simulated input is injected via ctx.ProcessInput before BeginFrame.
  • - Each scene gets a fresh ui::Context; the framebuffer is cleared per frame.
  • - Exit code is non-zero on unknown scene names or write failures — safe for

    • CI.

Tests

make test builds and runs aris_tests through CTest. The suite has zero external dependencies (a ~100-line assert harness in tests/test_main.hpp) and needs no GL context — it covers the pure logic:

  • - math: Vec2/Vec4/Rect/Color operators, blending, hex parsing
  • - easing: ExpSmooth frame-rate independence, monotonicity, EaseOutCubic,

    • EaseOutBack overshoot, CSS cubic-bezier reference values

  • - ids: FNV-1a 64 against published reference vectors
  • - command queue: push/pop/clip-depth accounting, full RectStyle propagation
  • - widget state store: target convergence, no overshoot, GC staleness
  • - layout: Yoga two-column rows, gaps, stretch, padding, absolute ChildRect

Add a test file under tests/, add it to aris_tests in CMakeLists.txt, follow the TEST(name) { ... CHECK(...); } pattern.

Docs fetching (LLM-friendly)

  • - docs/llms.txt — index of documentation pages (the emerging llms.txt

    • standard)

  • - docs/llms-full.txt — every documentation page concatenated in one file
  • - docs-src/*.md — the same content as plain Markdown, readable directly

    • from the repository

The HTML site in docs/ is generated by tools/gen_docs.py (stdlib-only) from docs-src/*.md. Edit the Markdown, run make docs, commit both — the sources are the single source of truth.

GitHub Pages

The docs/ folder is self-contained and designed to be served by GitHub Pages: repository Settings → Pages → deploy from branch main, directory /docs. No build workflow required.

Instrumentation in the runner

The interactive runner takes environment switches — handy for agents even though the preview tool is preferred:

  • - ARIS_DUMP=N — save the framebuffer as dump_N.png on frame N, then keep

    • running

  • - ARIS_DEBUG=1 — per-frame flush stats (vertex counts, atlas, px-range)
